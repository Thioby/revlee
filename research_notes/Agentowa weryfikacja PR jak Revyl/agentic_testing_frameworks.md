## Key Question 1 — Per-framework inventory (what it does, platforms, perception, assertions, caching, CI, evidence, license, stars, activity, LLM support)

### Takeaway
Three distinct layers exist: (a) **device/browser control layers that an LLM drives** (agent-device, mobile-mcp/mobilecli, Playwright MCP, Appium MCP, Maestro MCP, Argent, Browser Use, Midscene); (b) **test frameworks that embed an agent inside a test runner with deterministic replay** (tester-army/e2e is the only mobile+web one with a documented, verified-step replay cache; Midscene has a plan/XPath cache for web; Stagehand v4 has a server-side cache; Shortest is effectively unmaintained); (c) **autonomous task agents** (mobilerun, Skyvern, UI-TARS, Browser Use) that are optimized for task completion, not regression testing. For a self-built Revyl-like PR verifier on iOS Simulator + Android Emulator, the two most complete OSS building blocks are `tester-army/e2e` (Apache-2.0, 0.20.0, 2026-10-12) on top of `callstack/agent-device` (MIT, 0.21.27, 2026-10-12); `mobile-next/mobile-mcp` + `mobilewright` is the main alternative stack.

### Cited Findings

#### tester-army/e2e (`e2e`, `@e2e-dev/*`)
- Purpose: "Describe a goal in natural language and an agent drives the app to reach it." Test code mixes agent steps with locator assertions: `await agent.act('upgrade the workspace to the Pro plan'); await agent.assert('the invoice preview shows a prorated amount'); await expect(screen.getByRole('status')).toContainText('Pro');` — [GitHub README](https://github.com/tester-army/e2e)
- Platforms: `@e2e-dev/web` runs Chromium/Firefox/WebKit via Playwright; `@e2e-dev/mobile` runs iOS simulators and Android emulators via agent-device; hosted runner packages `@e2e-dev/kernel`, `@e2e-dev/limrun`, `@e2e-dev/eas`, `@e2e-dev/smol`; examples for Vite, Next.js, Astro, Expo, SwiftUI, Jetpack Compose, KMP, Flutter — [GitHub README](https://github.com/tester-army/e2e)
- Status: "e2e is in active development on the way to 1.0. APIs and config can still change between minor releases." License Apache-2.0; 10.3k stars; 777 commits on main — [GitHub README](https://github.com/tester-army/e2e)
- Versions: `e2e` 0.20.0 published 2026-10-12; `@e2e-dev/mobile` 0.12.0 published 2026-10-12 (package first created 2026-09-28); license field Apache-2.0; bin `e2e` — [npm registry](https://registry.npmjs.org/e2e), [npm registry @e2e-dev/mobile](https://registry.npmjs.org/@e2e-dev/mobile)
- Latest releases (12 Oct): `e2e@0.20.0` adds `e2e run --watch`; `@e2e-dev/mobile@0.12.0` breaking: iOS `device.setNetwork('offline')` / `setAirplaneMode(true)` now fail with `UNSUPPORTED_CAPABILITY`, `device.fold` on foldable Android emulators, locator matching now follows agent-device rules (`role=textbox` → `role=text-field`); `@e2e-dev/limrun@0.2.0` adds Limrun hosted device provider with recording via agent-device — [GitHub releases](https://github.com/tester-army/e2e/releases)
- Perception: "The first prompt includes a redacted text snapshot of the screen: roles, names, text, and states. It has no raw HTML, cookies, headers, or environment values." After each action the model gets screen diffs or a new full snapshot; node ids stay stable. `vision: true` adds a masked screenshot; `vision: 'only'` judges from the screenshot alone. "Pixel tools let the agent take a screenshot and act at a point when the text snapshot can't describe a control." No screenshot reaches the model after a secret fill — [docs/agent-steps.mdx](https://github.com/tester-army/e2e/blob/main/docs/agent-steps.mdx)
- Assertion API (exact): `assert(assertion: string, options?: AssertOptions): Promise<void>` with `vision?: VisionMode`, `timeout?` (default `judgmentTimeout` 30000), `screenshot?: boolean` (failure evidence, on by default, denied after a secret fill), `agent?`. Budget: 2 model calls (judgment + repair). Errors `ASSERTION_FAILED`, `ASSERTION_INCONCLUSIVE`. `type VisionMode = boolean | 'only'`. `act()` does **not** accept `vision` (throws `UNSUPPORTED_CAPABILITY`); `waitFor()` and `extract()` do. `extract<Schema extends StandardSchemaV1>(instruction, { schema, vision?, timeout?, agent? })` returns typed value; `MODEL_OUTPUT_INVALID` after repair round — [docs/reference/agent.mdx](https://github.com/tester-army/e2e/blob/main/docs/reference/agent.mdx)
- Budgets table: `act` maxModelCalls 25 / maxSteps 25 / timeout 120000; `waitFor` 25 model calls, interval default 3000 ms, re-judges only when screen changed; `extract` and `assert` 2 model calls, 30000 ms — [docs/reference/agent.mdx](https://github.com/tester-army/e2e/blob/main/docs/reference/agent.mdx)
- Pixel visual regression: `toHaveScreenshot` "compares what the app shows with a PNG stored next to the test file" and "works on every engine that captures pixels" (web, iOS sim, Android emu with the same test) — [docs/visual-testing.mdx](https://github.com/tester-army/e2e/blob/main/docs/visual-testing.mdx)
- Model support: models come via Vercel AI SDK providers ("There is no default"); examples: `gateway('openai/gpt-6-luna-fast')` with `AI_GATEWAY_API_KEY`, OpenRouter (`@openrouter/ai-sdk-provider`), OpenAI (`@ai-sdk/openai`), local/OpenAI-compatible (`@ai-sdk/openai-compatible` with `baseURL: http://127.0.0.1:11434/v1` for Ollama), Anthropic via `@ai-sdk/anthropic`; separate optional `judge` model for assertions/extraction; subscriptions page lists ChatGPT, Copilot, OpenCode Console, SuperGrok. Model must support tool calls and images — [docs/models.mdx](https://github.com/tester-army/e2e/blob/main/docs/models.mdx)
- Mobile engine config: `app.bundleId`, `appPath` (`.app` / `.apk`), `app.launchArguments`, `app.permissions` (set pre-launch so no system prompt), `device.installApp()`, `device.openLink()` for deep links, `device` fixture for appearance/network/airplane/keychain/fold without model calls; `screen.getByTestId` reads iOS accessibility identifier or Android resource id; `mobileTools(...)` adds `open_app`, `swipe`, `alert` agent tools; "Replay cache keys on the bundle id and screen title, not a page path." — [docs/mobile.mdx](https://github.com/tester-army/e2e/blob/main/docs/mobile.mdx)
- Telemetry: anonymous usage data; opt out with `npx e2e telemetry disable` or `E2E_TELEMETRY_DISABLED=1` — [GitHub README](https://github.com/tester-army/e2e)
- Third-party summary (vendor-ish): taps are stored as element descriptions (role, name, test ID) not coordinates so cache works across simulators; "only agent.assert still runs live" — [TestMu AI blog via search](https://www.testmuai.com/blog/e2e-by-testerarmy/) (page itself unreachable; claim from search snippet)

## Key Question 3 — tester-army/e2e: agent step caching, reports/traces, self-hosted GitHub Actions for iOS and Android

### Takeaway
e2e records a verified `agent.act` step as a JSON entry (target descriptions by role/name/testId + end-state checks, no screenshots/prompts), keyed on test/target/instruction/params/agent/engine/project/app identity, and replays it with zero model calls until route/control/end-state checks fail; strict mode turns staleness into a build failure. Reports are `.e2e/report.json` + `junit.xml` + per-test `trace.md` + PNG/WebM/MP4 artifacts, and the documented GitHub Actions jobs use hosted `macos-26` (xcrun simctl) and `ubuntu-latest` with KVM (reactivecircus/android-emulator-runner) — the docs do not describe self-hosted runners.

### Cited Findings
**What is cached and where**
- Cached: "Recorded actions, target descriptions (role, name, test id, surrounding context), typed text, a step summary, and end checks (the route plus up to eight controls that appeared and eight that went away)." Entries contain "no prompts, conversations, screenshots, observed trees, or secret values. A secret fill stores only the secret's name." Bare-point taps/hovers are recorded; replay is refused on a different viewport size — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- Location: "Each entry is a JSON file under `.e2e/cache/`, named by a hash of its key"; configurable `cache.dir` and `cache.store` — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- Recording rule: in `read-write` mode the runner saves at the end of the attempt "only if a later check passed. Locator matchers like `toHaveText` count. `agent.assert`, `agent.waitFor`, and `agent.extract` do not." `step.cache.write` ∈ {`saved`, `kept`, `unconfirmed`, `evicted`, `no-change`, `not-written`}. A failing attempt keeps verified steps and deletes unverified/failed entries; model-unavailable failures delete nothing — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- Key: "covers the test, target, instruction, params, agent (and its context), engine, project id, and app identity. Changing the model or upgrading the engine does not cause a miss by itself." Use `unique()` for per-run values; `app.identity` for changing preview URLs — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- Mobile key: "Replay cache keys on the bundle id and screen title, not a page path." — [docs/mobile.mdx](https://github.com/tester-army/e2e/blob/main/docs/mobile.mdx). CI page: "The replay cache key tracks the app, not the device, so recordings replay on CI devices." — [docs/ci.mdx](https://github.com/tester-army/e2e/blob/main/docs/ci.mdx)
- Key internals (from issue): entries keyed on `paramsDigest`, `callIndex`, `agent`; pre-0.17 entries stored only `testId`, `targetId`, `instructionDigest`; key changes (0.13 engine minor, #929 dropping engine version) orphaned 22 committed recordings on a 0.18 upgrade — [issue #938](https://github.com/tester-army/e2e/issues/938)

**Replay and invalidation**
- Replay: (1) check starting route matches; (2) find each recorded control by role, name, test id, context and repeat its action; (3) check final route and recorded UI changes; (4) finish with no model call, or hand off to the agent with a record of what ran. Routes compare origin/path/query with ids/tokens/cache-busters as placeholders — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- Miss/hand-off reasons: `no-entry`, `wrong-context`, `target-not-found`, `target-ambiguous`, `action-failed`, `action-uncertain`, `viewport-changed`, `end-mismatch`, `gap`, `truncated`; exposed as `step.cache.reason` / `step.cache.detail`; `retry` steps never replay except in strict mode; gaps include mutating project tools and values read from screen/date — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- Modes: `read-write` (default locally), `read-only` (default in CI when `cache` unset), `off` (`--no-cache`). `--strict-cache` / `cache: { strict: true }`: stale recording fails with `REPLAY_STALE` (exit code 2, not retried); strict runs never write/delete. `npx e2e cache ls|stats|clear` — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- CI recommendation: `e2e init` gitignores `.e2e/cache/`; to share replays remove that line and commit; "Treat committed entries as test data and review them in pull requests. Typed values are stored as typed"; recommended: commit recordings and run `--strict-cache` so stale entries fail the build "rather than silently incurring model costs" — [docs/cache.mdx](https://github.com/tester-army/e2e/blob/main/docs/cache.mdx)
- Open gap (Oct 6 2026, P2): strict+read-only still runs never-recorded steps live (`no-entry` not in `STALE_REASONS`), legacy entries treated as unrecorded, and `assert`/`waitFor`/`extract` always call the model (`maxModelCalls` cannot be 0); proposal `cache.replayOnly: true` / `--replay-only` with `REPLAY_MISSING`; linked PR #961 — [issue #938](https://github.com/tester-army/e2e/issues/938). Related: PR #923 "--strict-cache replays on retries and never writes the cache"; issue #850 trace-cache `endWaitMs` grows to `MAX_TRACE_END_WAIT_MS` 120 s — [PR #923](https://github.com/tester-army/e2e/pull/923), [issue #850](https://github.com/tester-army/e2e/issues/850)

**Reports and traces**
- Layout: `.e2e/results/<test>/trace.md` (default for failed/timed-out/interrupted/flaky), `attempt-<n>/` with `screen-at-failure.txt`, `screenshots/`, recordings, downloads, agent transcripts; `rerun-<n>/`; `.e2e/report.json` (versioned schema; failed result's last attempt has `error`, `failure`, `steps`, `appLog`, `artifacts`); `.e2e/summary.md` (markdown reporter); `.e2e/ai-trace.json` (`--ai-trace`). Formats: markdown traces, WebM (web) / MP4 (devices) video, PNG screenshots, JSON report. Flags: `--trace`, `--trace off`, `--video`, `--video=retain-on-failure`, `--video=on-first-retry`, `--headed`, `--debug`, `--ai-trace`, `--no-cache`, `--reporter json`. Per step: duration, model calls, tokens in/out, prompt-cache share, cost; trace page shows node acted on, assertion values, replay cache decision, app log lines, navigation, screen changes. "A replayed step makes no model call and writes no AI trace entry." No HTML report described — [docs/debugging.mdx](https://github.com/tester-army/e2e/blob/main/docs/debugging.mdx)
- `--reporter list,junit` → `.e2e/junit.xml` incl. startup failures like `APP_UNREACHABLE`; upload `.e2e/` including on failure — [docs/ci.mdx](https://github.com/tester-army/e2e/blob/main/docs/ci.mdx)
- PR comment reporter `@e2e-dev/github`: one comment per run, updated on rerun; headline pass/fail/flaky/skipped + agent steps, model calls, tokens (cached share), cost; failures with source link, failing step, assertion message, last agent actions, links to screenshots/video artifacts and trace page; needs `pull-requests: write` and `GITHUB_TOKEN` in step `env`; forks get read-only token; `github({ key: process.env.MATRIX_BROWSER })` for matrices; `npx e2e run || npx e2e run --last-failed` — [docs/github.mdx](https://github.com/tester-army/e2e/blob/main/docs/github.mdx)

**CI on GitHub Actions (iOS/Android)**
- General: any CI running Node 24.8+ (or 22.22.3+); covers GitHub Actions, EAS Workflows, Bitrise, Codemagic, "Mac mini or Linux runners"; CI mode when `CI` set: retries default 1, workers 1, cache read-only, `.only` rejected (`ONLY_IN_CI`); `--workers`, `--retries`, `--shard <index/total>`, `--pass-with-no-tests`, `--last-failed`, `--max-failures <n>`; "For mobile, cache `~/.agent-device`, where agent-device builds its XCUITest runner." - GitHub Actions page: iOS job on `macos-26`, 60-min timeout, `xcodebuild` Release `-derivedDataPath build` (or `npx expo run:ios --device generic --no-bundler --output build/ios`), cache `~/.agent-device` keyed on OS + `package-lock.json` hash, `xcrun simctl create` → `xcrun simctl bootstatus -b` → `xcrun simctl install`, runtime pinned e.g. `com.apple.CoreSimulator.SimRuntime.iOS-26-5`, `npx e2e run --target ios --reporter list,junit`, upload `.e2e` as `e2e-ios`. Android job on `ubuntu-latest`, KVM via udev rule, Temurin Java 17, `./gradlew :app:assembleRelease`, `reactivecircus/android-emulator-runner` v2.38.0 (API 36, x86_64, google_apis, pixel_7, headless, swiftshader, no snapshots/audio, animations off), `adb install -r` + `npx e2e run --target android` in the same script step. "The page doesn't mention self-hosted runners." Repo's own `mobile.yml` adds cached Expo build keyed to native fingerprint, two simulators for two workers, `--last-failed` rerun — [docs/ci/github-actions.mdx](https://github.com/tester-army/e2e/blob/main/docs/ci/github-actions.mdx)

## Key Question 5 — Known flakiness / determinism / cost problems reported by users

### Takeaway
Public evidence is thin and mostly vendor-authored; the concrete data points are Slack's $15–30 per agentic run (context re-sending dominates), TestMu's ~20% path consistency for Playwright-MCP agents, Maestro `assertWithAI` false negatives and an MCP multi-simulator port-sharing bug, and e2e's own issues showing cache-key churn and model calls leaking into "replay" CI runs. No HN or Reddit threads specific to these tools were found.

### Cited Findings
- Slack Engineering: agent-driven E2E runs "typically cost $15–30 per execution, and that most of the spend was re-sending content the model had already seen"; cost driven by context accumulation and number of turns, not output; mitigations: prompt caching, context compaction; "the way the agent was executed mattered more than which model powered it" — [slack.engineering (search snippet; page unreachable)](https://slack.engineering/agentic-testing-where-agents-fit-in-the-e2e-testing-stack/)
- TestMu AI: "only ~20% of runs took the same path with Playwright MCP agents"; recommends checking outcomes rather than paths and "replaying passed steps without fresh reasoning" — [testmuai.com (search snippet; page unreachable)](https://www.testmuai.com/blog/agentic-testing-e2e-stack/)
- Augment Code guide: agent E2E failures from brittle selectors, timing failures in CI, schema drift — [augmentcode.com](https://www.augmentcode.com/guides/why-ai-coding-agents-fail-e2e-tests)
- Maestro `assertWithAI`: false result with wrong explanation (#2116); reasoning about the wrong year caused a date mismatch (#2812) — [#2116](https://github.com/mobile-dev-inc/maestro/issues/2116), [#2812](https://github.com/mobile-dev-inc/maestro/issues/2812)
- Maestro MCP determinism bug (opened 2026-09-18, Maestro 2.10.0, open with PR #3647): "every iOS Simulator session shares driver port 22087, so MCP calls can read and tap the wrong Simulator"; call still reports success; cached MCP sessions never recreated after runner stops — [#3611](https://github.com/mobile-dev-inc/Maestro/issues/3611)
- Maestro general flake: "the tap that fails because the screen hasn't rendered yet as the most common flake" — [codeline.co via search](https://www.codeline.co/thoughts/repo-review/2025/maestro-mobile-e2e-testing)
- e2e: cache key changes orphaned 22 committed recordings on 0.18 upgrade, causing live model runs in a CI gate meant to be zero-token; `assert`/`waitFor`/`extract` ignore cache — [issue #938](https://github.com/tester-army/e2e/issues/938); trace end-wait grows to 120 s per run — [issue #850](https://github.com/tester-army/e2e/issues/850)
- e2e design mitigations: `waitFor` makes no model call while screen unchanged; "A screenshot adds input tokens to every call that carries it"; loop detection (after 3 failed actions model told to change approach, after 5 asked for verdict); `--max-failures` to stop "wasting model calls after a broken deploy"; flaky tests marked in report — [docs/agent-steps.mdx](https://github.com/tester-army/e2e/blob/main/docs/agent-steps.mdx), [docs/ci.mdx](https://github.com/tester-army/e2e/blob/main/docs/ci.mdx)
- Midscene explicitly warns its cache "is not a tool for ensuring long-term script stability" and that misses fall back to AI (cost) — [caching.mdx](https://github.com/web-infra-dev/midscene/blob/main/apps/site/docs/en/caching.mdx)
- Stagehand v4 cache only works with Browserbase browsers (no local cache), i.e. deterministic replay is tied to the vendor cloud — [docs.stagehand.dev via search](https://docs.stagehand.dev/v4/best-practices/caching)
- Shortest: issue #449 "Current Anthropic API keys (sk-ant-api03) are not supported – Shortest fails with Max retries error" (fixed Aug 2025) — [commits](https://github.com/antiwork/shortest/commits/main)
- FinalRun HN reception (second-hand): praise for simplicity, concerns "about accuracy, questioning how well the AI handles edge cases like varying screen sizes" — [feedbagel via search](https://feedbagel.com/post/finalrun-agent-ai-powered-cli-tool-for-automated-mobile-app-testing)
- e2e CI doc on iOS version drift: "accessibility trees change between iOS versions" (reason to pin runtime) — [docs/ci.mdx](https://github.com/tester-army/e2e/blob/main/docs/ci.mdx)

### Inferences
- The recurring pattern across sources: live agent runs are non-deterministic in *path* and expensive in *context*; every serious framework converges on "agent once, replay deterministically, re-agent only on drift" (e2e cache, Midscene cache, Stagehand cache, agent-device `.ad`, Argent Flows). A Revyl-like system should budget for model calls on first run and on drift, and make assertions locator-based wherever possible to keep replay runs at zero tokens.
- Vision-only assertion (`vision: 'only'`, `assertWithAI`) is the least reliable and most expensive judgment mode per the Maestro issues and e2e's token note; use it as a fallback for canvas/custom-drawn UI.

- No Hacker News or Reddit threads specific to agent-device, e2e, mobile-mcp, mobilerun, Midscene or Maestro MCP were found (HN search returned unrelated threads; Reddit blocked to the search tool).
- Slack and TestMu posts could not be opened; figures are from search snippets only.
- No published cost-per-run data for e2e, agent-device, mobilerun, or Midscene mobile flows beyond Midscene's AppControlBench "$0.59 total" claim.
